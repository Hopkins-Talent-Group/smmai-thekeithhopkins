## Why This Sprint Exists

The audit scored the repo 3/10. That number is not about code quality — it's about three specific facts:

1. **The dashboard does not build.** `pnpm build` fails with 50+ TypeScript errors.
2. **Persistence is fake.** `src/lib/prisma.ts` is a hand-written stub. Every CRM write returns `null` or `[]`.
3. **The built feature is unreachable.** `ClientsTable.tsx` exists but `dashboard/page.tsx` renders a placeholder.

And the meta-problem: **CI runs on the Python half of the repo and never touches the Next.js app.** Every P0 in this list would have been caught automatically by pointing CI at the dashboard. That's the fix with the highest leverage per hour of work.

---

## The Required Outcomes

By end of Day 3, this must be true:

| Outcome | Verification |
|---------|-------------|
| Dashboard builds | `pnpm build` completes with zero errors |
| Persistence works | Creating a client survives a page refresh |
| Feature is reachable | Clients tab renders the real table, not a placeholder |
| Routes are protected | `/dashboard` and `/api/crm/*` require auth |
| CI catches regressions | A deliberately broken PR fails CI before merge |

If any of those is false at end of Day 3, the sprint is not complete.

## Day 1 — Make It Build, Make It Real

**Focus:** Remove every reason `pnpm build` fails.

### 1.1 — Pin Prisma CLI to stable

`devDependencies` contains `prisma@8.0.0-rc.17` — a pre-release of a different, still-changing CLI product with **no `generate` command**. `@prisma/client` and `@prisma/adapter-neon` are correctly pinned to stable `7.10.0`.

```bash
cd nextjs-setup/nextjs-dashboard
pnpm remove prisma
pnpm add -D prisma@7.10.0
pnpm exec prisma --version   # must print 7.10.0
```

**Commit:** `chore(deps): pin prisma CLI to 7.10.0`

### 1.2 — Move datasource config to `prisma.config.ts`

Prisma 7 rejects `url`/`directUrl` inside the `schema.prisma` `datasource` block. Connection config belongs in `prisma.config.ts` at the dashboard root.

Verify: `pnpm exec prisma validate` returns *"The schema at prisma/schema.prisma is valid"*.

**Commit:** `fix(prisma): move connection config to prisma.config.ts`

### 1.3 — Generate the real Prisma client

`src/lib/prisma.ts` and `src/generated/prisma/index.ts` are **hand-written stubs**. Every method returns `[]`, `null`, or a hardcoded object regardless of input. Nothing a user creates survives a page refresh.

Steps:
1. Back up the stubs to `.stub-backup` files.
2. Run `pnpm exec prisma generate`.
3. Confirm `src/generated/prisma/` now contains real generated files (`index.d.ts`, `runtime/`, etc.).
4. Rewrite `src/lib/prisma.ts` as a real client export with the global singleton pattern.
5. Delete the `.stub-backup` files after verification.
6. Confirm `src/generated/prisma/` is gitignored before committing.

**Commit:** `fix(prisma): replace stub client with real generated client`

### 1.4 — Resolve TypeScript build errors

Run `pnpm build` and capture the full output. Group errors by file. The largest cluster is `src/lib/crm.ts` and its interaction with `src/generated/prisma/index.ts` — specifically `ClientStatus` written as a type union where a runtime value was needed.

Fix one file at a time. **Do not** add `ignoreBuildErrors: true` to `next.config.ts` — that defeats the purpose of the sprint.

**Commit:** `fix(types): resolve TypeScript build errors in CRM layer`

### Day 1 Gate

```
cd nextjs-setup/nextjs-dashboard
pnpm install
pnpm build
```

**Required:** zero errors. Report commits + build output. Wait for approval.

## Day 2 — Make It Secure, Make It Reachable

**Focus:** Protect the app. Connect the feature that already exists.

### 2.1 — Add auth enforcement middleware

There is no `middleware.ts` in the project. Every `/dashboard` route and every `/api/crm/*` route is open to anyone with the URL.

Create `src/middleware.ts` that:
- Redirects to `/login` for unauthenticated `/dashboard/*` requests
- Returns 401 for unauthenticated `/api/crm/*` requests
- Does **not** gate `/api/auth/*`, `/login`, or `/`

Follow the existing session pattern in `src/lib/auth.ts` and `src/app/api/auth/login/route.ts`. Do not invent a new system.

**Commit:** `feat(auth): add middleware to gate dashboard and CRM routes`

### 2.2 — Wire the Clients table into the dashboard

`ClientsTable.tsx`, `ClientForm.tsx`, and `ClientStatsCards.tsx` are complete, working components. `dashboard/page.tsx` renders a static placeholder paragraph for the `clients` case instead of them.

Replace the placeholder with the real component. Ensure the data source is wired correctly.

**Commit:** `feat(dashboard): wire ClientsTable into clients view`

### 2.3 — Persist the dry-run toggle

`src/app/api/crm/status/route.ts` stores `dryRun`/`wasmRanking` in a module-level `let`. On serverless, this does not survive between invocations. The one flag between simulated and live posting is unreliable by construction.

Add a `SystemSetting` model to the Prisma schema (`key String @id`, `value String`, `updatedAt DateTime @updatedAt`). Migrate. Rewrite the route to read/write from the database.

**Commit:** `fix(crm): persist dry-run toggle to database`

### 2.4 — Delete dead code

Verify with `grep` that these are unreferenced before deleting:
- `src/components/crm/ClientManagement.tsx` (placeholder)
- Any duplicate `CRMDashboard.tsx`

**Commit:** `chore: remove dead components`

## Day 3 — Make It Stick

**Focus:** Prevent regression. Clean up outstanding low-effort items.

### 3.1 — Point CI at the Next.js app

`.github/workflows/ci.yml` runs `ruff` and `pytest` on the Python package only. **It never touches the Next.js dashboard.** This is the single biggest process gap in the repo — a real CI pipeline exists and it would have caught every P0 in this sprint automatically, for free, on every PR, if it had been aimed at the correct folder.

Add a job that runs `pnpm install --frozen-lockfile`, `pnpm build`, and `pnpm lint` inside `nextjs-setup/nextjs-dashboard`. Make it a required check.

**Commit:** `ci: add Next.js build and lint to CI pipeline`

### 3.2 — Fix ClientForm status casing

`ClientForm.tsx` uses `status: "prospect"` (lowercase). The API validates against uppercase `PROSPECT`. This is a silent runtime failure once persistence is real.

**Commit:** `fix(crm): use uppercase ClientStatus values in form`

### 3.3 — Fix root lockfile mismatch

Root `package.json` declares `next@14.2.6` with no matching entry in the root `pnpm-lock.yaml`. `pnpm install --frozen-lockfile` fails at the repo root today.

Remove the stray dependency (if unused at root) or regenerate the lockfile.

**Commit:** `chore: fix root lockfile mismatch`

### 3.4 — Remove unnecessary subprocess

`src/smm/main.py`'s `compute_engagement_rate` spawns `subprocess.run(["python3", "-c", f"...{impressions}..."])` with request values interpolated into the executed string, then computes the identical result two lines below as a documented fallback. The subprocess is unnecessary and is unneeded attack surface.

Delete the subprocess block. Keep the safe fallback. Run `pytest`.

**Commit:** `fix(smm): remove unnecessary subprocess in engagement rate`

### 3.5 — Clean up workspace placeholder

`nextjs-setup/nextjs-dashboard/pnpm-workspace.yaml` contains a committed literal placeholder: `allowBuilds: { unrs-resolver: set this to true or false }`. Either answer it or remove the block.

**Commit:** `chore: remove unfilled workspace placeholder`

## Rules During the Sprint

1. **No new features.** Not one. This is remediation only.
2. **No refactoring beyond what's listed.** If it isn't in this document, don't touch it.
3. **Commit after every task.** Small commits, clear messages, easy to bisect.
4. **`pnpm build` after every task that changes TypeScript.** If it breaks, fix it before moving on.
5. **No `git clean`, no `git reset --hard`, no force pushes.** Refer to the safety rules in `AGY-SPRINT.md`.
6. **No commits to `main`.** `dev` only.
7. **No secrets in commits.** Run `git status` and check the staged list before every commit.

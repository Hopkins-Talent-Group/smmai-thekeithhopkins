Safety by default

Automation with control built in

Live publishing is deliberately constrained until platform permissions and API behavior are validated.

Dry-run first

Development and scheduled QA use DRY_RUN=true. The Meta adapter does not send live requests in dry-run mode.

Secrets stay out of source

OAuth tokens, API keys and refresh tokens belong in environment variables and GitHub Secrets, not config files or commits.

Moderation before publish

A failed policy check blocks publication. Empty content and missing required disclosures are rejected.

Explicit approval

The publishing service requires a human approval signal before a live publish can proceed.

Build sequence

Start focused. Expand behind adapters.

  1. Meta / Instagram and Facebook Page Completed

    Publishing adapter, moderation, human approval gate and analytics feedback loop.

  2. LinkedIn and X In progress

    Multi-platform text and post expansion. Single planner, per-network adapter.

  3. TikTok and YouTube Upcoming

    Video content and short/long-form publishing through the same adapter contract.

  4. Analytics-driven recommendation loop Planned

    Performance scoring and topic prioritization feeding back into the planning stage.
